# 单 HTML 打开与覆盖保存设计

## 目标

为现有 HTML Studio 增加可写文件工作流：用户可以打开一个 HTML 文件，或打开一个只包含单个入口 HTML 的项目文件夹，完成编辑后将源码覆盖保存回原 HTML。

## 范围

- 支持打开单个 `.html` 或 `.htm` 文件。
- 支持打开文件夹，并沿用现有入口规则：优先选择层级最浅的 `index.html`，否则选择发现的第一个 HTML。
- 文件夹中的 CSS、JavaScript、字体和图片继续作为入口 HTML 的项目资源加载。
- 新增“覆盖保存”操作，将编辑器中的当前源码写回入口 HTML。
- 保留现有“导出 HTML”和“导出 ZIP”作为兼容与备份方式。

不支持同时编辑或切换多个 HTML，不增加 PPT 页面缩略图、多页面历史记录或批量保存。

## 交互设计

顶部项目操作区提供“打开 HTML”“打开文件夹”和“覆盖保存”。打开成功后显示当前文件名或相对路径。“覆盖保存”仅在当前会话持有可写 HTML 文件句柄时启用。

打开新文件前继续依赖现有草稿机制保护编辑内容。保存成功后状态显示“已保存”，保存失败则保留编辑器内容并显示明确错误。

## 文件权限与兼容

支持 File System Access API 时：

- “打开 HTML”使用 `showOpenFilePicker`，保存返回的文件句柄。
- “打开文件夹”使用 `showDirectoryPicker`，递归读取目录，确定入口 HTML，并保存入口文件句柄。
- “覆盖保存”通过 `createWritable()` 写入当前源码，成功后关闭写入流。

不支持该 API 时，打开操作回退到现有文件输入和文件夹输入。回退方式只能读取文件，因此“覆盖保存”保持禁用，并通过按钮提示说明用户可使用“导出 HTML”。

用户拒绝授权、取消选择或文件在外部被移除时，不清空当前编辑内容。取消选择不显示错误；权限或写入错误显示在现有源码状态区域。

## 状态与数据流

应用状态新增当前入口文件句柄和打开来源类型。单文件打开后清理项目资源；文件夹打开复用现有项目状态、资源 URL 重写和 ZIP 导出逻辑。

覆盖保存写入 `sourceEditor.value`，即用户正在编辑的原始项目源码，不写入用于 iframe 预览的资源 URL 重写结果，也不注入编辑器内部标识。

加载示例、恢复浏览器草稿或使用只读上传回退时清除可写文件句柄，防止覆盖到之前打开的文件。

## 验证

- 打开单个 HTML 后内容、预览、文件名和覆盖按钮状态正确。
- 打开带资源的单入口 HTML 文件夹后预览正常，覆盖保存只修改入口 HTML。
- 覆盖保存写入的是干净源码，不含预览桥接代码或 `data-editor-id`。
- 取消文件选择、拒绝权限和写入失败不会丢失当前内容。
- 不支持 File System Access API 时仍可上传和导出，覆盖按钮不可用。
- 现有文件夹导入、资源替换、导出 HTML、导出 ZIP 和编辑器状态检查继续通过。
